# 界面动效精修说明

更新日期：2026-10-22。适用项目：团结 1.10.4／微信小游戏「我就划两下」。

本轮延续暖纸张、棕色墨迹、金色边框和宝石色道具的画面方向，在上一轮已调整的首页、道具商店、成就与好友、登顶活动布局上增加统一素材与轻量动效。正文继续使用清晰的中文字体，标题与按钮保留活泼的展示字体；本轮功能文案、价格、数量与达成状态仍由代码绘制。

## 已落实的动效

| 位置 | 当前实现 | 时序与限制 |
| --- | --- | --- |
| 页面进入 | 菜单内容轻移并淡入，使用缓出曲线；页面适配根节点继续负责布局 | 单项 0.22 秒，最大错峰 0.08 秒；钱包、背景、底部导航和好友共享画布不参与此进入位移 |
| 按钮按压 | 只缩放按钮视觉子层，点击区域和原回调保持稳定 | 按下缩至 0.97，耗时 80 毫秒；释放恢复耗时 140 毫秒；移出、取消和页面关闭时恢复 |
| 成就进度 | 进度条视觉展开至实际通关进度 | 默认 0.35 秒，不改变通关数和达成条件 |
| 成就徽章 | 达成的宝石勋章显示少量金色星光；五级数字色章区分阶段 | 每层每次 3 颗；未达成徽章保持静态并降低图标不透明度 |
| 商店道具 | 新道具插画小幅漂浮，魔法笔配低频星光 | 漂浮幅度 4 个参考画布单位；魔法笔每次 3 颗星光 |
| 金币兑换成功 | 成功提示中显示对应道具插画和一次金色庆祝 | 一次 10 颗星光；仍使用现有金币兑换、持有数量更新与音效回调 |
| 活动邀请页 | 七岛旅程插画轻浮动，宝箱区域有柔光和少量星点 | 插画幅度 6 个参考画布单位，每次 3 颗星光 |
| 活动进行页 | 当前岛底层金环标示位置，头像小幅浮动；主宝箱配柔光和星点 | 当前节点每次 2 颗，宝箱每次 4 颗；头像幅度通常 7，冷却态 3 |
| 活动登顶 | 未领取奖励时，宝箱展示一次庆祝 | 每次打开该未领取状态页面时播放一次；领取后不再播放此庆祝 |

星光循环在每次短暂闪烁结束后等待约 2.1～3.7 秒。每个星光发射层使用固定容量数组，**单层粒子上限为 12**；此数值不是整页多个星光层合计的上限。光环和柔光使用简单静态网格，不新增特效贴图或独立材质，装饰图形不接收点击。

主要实现位置：`Assets/Scripts/UI/MenuMotion.cs`、`Assets/Scripts/UI/MenuUI.cs`、`Assets/Scripts/Runtime/SourceShop.cs`、`SourceCollection.cs`、`SourceClimb.cs`。活动原有 `ClimbPageMotion` 保留业务倒计时刷新；角色与插画的漂浮交由统一动效组件处理。

## 精简动效

设置页新增「菜单动效：完整／精简」，使用存档字段 `PlayerProfile.reducedMenuMotion` 保存偏好。精简时页面立即处于最终位置，进度条直接显示目标值，按钮不进行缩放，菜单星光与漂浮停止；正在播放的视觉状态恢复。恢复完整动效后，循环星光按正常间隔继续，避免立即集中闪烁。

此偏好作用于本轮菜单装饰与交互反馈。活动倒计时、游戏倒计时、按钮操作、金币兑换和奖励领取继续正常工作。

素材只承担图形呈现，功能名、价格、数量、达成状态和数字色章均保留为可读文本，避免将业务信息烘焙进图片。

## 业务与音频范围

本轮没有修改棋盘与关卡规则、道具效果、金币兑换数量及价格、成就门槛、活动晋级、重试冷却或分奖计算。所有动画都不决定奖励发放，也不增加等待动画结束才能操作的业务条件。

音频沿用现有 83 条原版资源，本轮没有替换或增加音频。最终微信导出中的音频一致性仍需以当前版本的 `QA/WeChat/export-validation.json` 等验证记录为准，不能用本说明代替导出比对。

## 验证状态与证据

已完成的静态核对包括：新素材尺寸与透明通道、代码中的动效时序、图层与点击设置、精简动效分支、粒子固定容量，以及活动业务 Tick 与装饰漂浮的分离。

运行验证由 `Assets/Scripts/Runtime/MenuMotionQA.cs` 记录，输出至 `QA/MenuMotion/menu-motion-validation.json` 及 `QA/MenuMotion/frames/`。检查范围包括真实 uGUI 渲染帧、页面进入与输入、按压恢复、兑换结果、进度展开、星点容量、动态切换精简模式，以及多次切页后的动效生命周期。

首帧输入检查另有诊断记录：新建 uGUI 对象在第一次实际渲染前，其原生 `CanvasRenderer.depth` 为 `-1`，此时 `GraphicRaycaster` 会排除它。静态／精简动效对照也出现同一现象，因此测试改为先实际渲染初始帧、保持动画进度为 0，再对可见按钮执行同样的命中检查；三页均可命中。该检查没有等待动画结束，也没有通过延迟开放输入来通过测试。具体命中信息见动效 JSON 中的逐阶段诊断。

上述时间为 Windows 测试采样结果，不能据此推断真机帧率。**微信构建与官方 SDK 转换已完成，本轮尚未完成微信真机动效验收**；最终压缩流、资源、音频及包体校验见 `QA/WeChat/export-validation.json`。微信模拟器与真机结果需分别记录，不能由 Windows 检查替代。后续重跑结论以最新 JSON 的 `status`、`checks`、`errors` 和实际渲染帧为准。

`界面优化预览.html` 已加入9组真实采集动效中的主要示例，图像编码保留采样时序，并在结尾额外停留1秒便于观察。逐帧PNG保留在动效QA目录。预览文件的本地资源引用、JavaScript语法及动图逐帧解码检查见 `QA/MenuMotion/preview-page-validation.json`；未将浏览器排版或预览动图视为真机帧率测量。
