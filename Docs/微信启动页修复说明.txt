微信启动页图片修复与重构包

用户反馈的白屏破图来自进入团结场景之前的微信 SDK CoverView 启动页，背景和底部 Logo 使用了相对路径 images/background.jpg、images/unity_logo.png。工程中的原始 JPEG/PNG 可正常解码，当前没有运行现场可进一步确认相对路径失效的具体环节。

本次处理：
1. 保留 SDK 默认背景和引擎默认 Logo，不增加原游戏发行商品牌图。
2. 每次导出强制补齐两张图片，实际解码并记录尺寸、字节数和 SHA-256。
3. 启动时先读取包内原图字节，同步写入微信 USER_DATA_PATH 下带内容哈希的缓存文件，再把绝对路径交给 CoverView；不依赖加载层解析宿主相对路径。
4. 写入失败时明确输出警告并保留包内路径回退，不中断后续引擎启动。
5. 打包检查确保图片未被忽略，ZIP 内实际包含原图；启动入口测试覆盖 wxfile://usr 和开发环境 http://usr 两种路径。

加载页代码位于导出目录 inkomino-loading-assets.js，由 Assets/Editor/WeChatLoadingAssets.cs 与模板在每次构建末尾自动生成，不手改第三方 SDK 安装文件。
报告：QA/WeChat/loading-assets.json、loading-assets-validation.json、export-validation.json。
测试执行了最终 game.js 的启动配置链路，微信文件系统和管理器使用隔离桩；不将此测试声称为真实 CoverView 截图验证。导入新包后请观察初始化背景和底部 Logo。

此前微信原生存档、启动完成上报、图形兼容、新手引导、全部原版音频和中文界面均保留。AppID：wx3a628e8b48216b63。
